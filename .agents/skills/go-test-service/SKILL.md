# Web Harness：验证 Go 服务行为

独立调用时从根 Workspace 和本次请求确定服务成员、操作及变更类型；受委托时复用调用方提供的范围、契约、资源归属和已有证据。普通行为变化只运行相关非空测试；行为保持重构在服务成员 cwd 运行全量 `go test ./...`。默认使用 Go testing、httptest 与临时 SQLite；成功、最高风险失败、越权和重启持久化按本次变化覆盖。

handler、装配、协议或持久化变化，以及已分配的业务联调，必须启动真实服务，通过实际 HTTP 验证当前操作；存在受影响前端成员时再核对其 typed adapter 与错误恢复，纯 Server 不要求前端。健康接口只证明中性服务，不能代替用户、订单或钱包闭环。测试账号只创建在隔离数据库，不进入产品 fixtures 或仓库；服务端口、数据库与进程由当前测试精确拥有并回收。

身份/并发/事务变化按需要加 race 或多请求测试。先核对已有证据是否覆盖同一源码、操作和成员，只补缺失或修改后失效的检查；不因被多个叶子调用而重复测试。记录实际命令、源码状态、接口、持久化和失败恢复证据，未执行项明确报告。候选、浏览器和发布仅由相应独立事件触发，完成后返回调用方，不反向重启实施。
